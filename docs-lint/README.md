# Как писать код в StepanFactory

[Открыть HTML-разбор с примерами React, Reatom и Electron](project.html)

Все файлы в [examples](examples/) проходят TypeScript и Oxlint вместе с приложением. В [rejected](rejected/) лежат короткие нарушения. Команда `npm run docs-lint` проверяет, что разрешённые примеры проходят Oxlint, а каждое ожидаемое нарушение даёт нужное правило на нужной строке.

| Задача | Как писать | Где посмотреть |
| --- | --- | --- |
| Объявить функцию | Экспортируйте стрелку через `export const`. Для внутренней функции используйте `const` без экспорта. Это проверяет `project/const-functions`. | [Синхронная и асинхронная функции](examples/sessions.api.ts) |
| Описать тип | Интерфейсы, псевдонимы и объектные типы параметров выносите в соседний `*.types.ts`. Используйте `import type`. Правило `project/separate-types` также обнаруживает исполняемый код в файле типов. | [Тип сессии](examples/sessions.types.ts), [импорт в модуль API](examples/sessions.api.ts) |
| Объявить константу | Экспортируемые данные кладите в соседний `*.constants.ts`. В нём остаются только данные, функции переносятся в `*.domain.ts`. Это проверяет `project/constants-file`. | [Разделы навигации](../src/features/navigation/navigation.constants.ts) |
| Назвать файл компонента | Файл `session-panel.tsx` экспортирует `SessionPanel`. Это проверяет `project/filename-export`. | [Панель сессии](../src/features/sessions/session-panel.tsx) |
| Импортировать модуль | Импортируйте файл по его пути. `export *` и реэкспорт из другого модуля запрещает `project/no-barrel`. | [Точка сборки](../src/renderer/main.tsx) |
| Дождаться промиса | Используйте `await` и `try/catch`. `.then()` запрещён, `.catch()` допустим только в конце отдельной инструкции, когда синхронный обработчик запускает промис. Это проверяет `project/promise-chains`. | [Запуск окна](../src/main/index.ts) |
| Хранить и вычислять состояние | Объявите именованный `atom` для значения, `computed` для производного значения и `action` для команды. Имя передаётся вторым аргументом. | [Модель черновика](examples/named-model.ts) |
| Продолжить действие после ожидания | В асинхронном действии ожидайте `wrap(promise)`. Тогда следующий вызов модели выполнится в том же контексте Reatom. | [Сохранение](examples/async-action.ts) |
| Показать состояние в React | Вызовите атом при рендере внутри `reatomComponent`. Обработчик кнопки свяжите с действием через `wrap`. | [Кнопка счётчика](examples/counter-button.tsx) |
| Обработать внешнее значение | Примите `unknown` и сузьте тип проверкой. Для результата доступа по индексу учтите `undefined`. | [Чтение имени](examples/unknown-input.ts) |
| Дождаться асинхронной операции | Дождитесь промиса или верните его вызывающему коду. | [Ожидание сохранения](examples/await-save.ts) |
| Обратиться к возможностям ОС | Импортируйте Node и Electron в main. Модель renderer использует Reatom, а React-компоненты читают модель. | [Окно Electron](../src/main/index.ts), [модель](examples/counter.ts) |

## Что проверяется

`npm run lint` использует [конфигурацию Oxlint](../oxlint.config.ts). Включены категории correctness, suspicious и perf, правила импортов, хуков, доступности JSX и дополнительные строгие проверки TypeScript. Потерянные промисы, небезопасное использование значений типа any, утверждения типов и пропущенные варианты union в switch дают ошибку. Для именованных импортов React в renderer ограничены хуки локального состояния, эффектов, `useMemo` и `useCallback`. Роли файлов и границы импорта описаны в [архитектуре](../docs/architecture.md). Для статических импортов из модели дополнительно закрыты React и его адаптеры.

[Проектный плагин](../tooling/reatom.ts) определяет фабрики по импорту из `@reatom/core`, включая псевдонимы и namespace-импорты. Проверка имени действует на `atom`, `computed` и `action`. [Правило для await](../tooling/reatom-async.ts) проверяет асинхронные колбэки action, computed, effect и перечисленных в правиле хуков, включая локально объявленные обработчики. Обычные async-функции могут использовать await напрямую.

`npm run typecheck` проверяет main, renderer, инструменты и разрешённые примеры. В renderer включён `skipLibCheck` из-за ошибок в опубликованных декларациях `@reatom/core@1001.3.0` с TypeScript 7. Сигнатуры библиотеки продолжают проверяться в местах вызова.

## Как добавить правило

1. Сначала запишите небольшой пример желаемого кода в `examples/`.
2. Добавьте нарушение в `rejected/`, затем укажите файл, строку и код ошибки в [verify.ts](verify.ts).
3. Запустите `npm run docs-lint`. Если проверка уже проходит, текущее правило покрывает этот случай.
4. Если диагностики нет, включите встроенное правило или добавьте обработчик в `tooling/` и подключите его в конфигурации. Сообщение проектного правила должно объяснять исправление и указывать на пример.
5. Выполните `npm run check`, чтобы проверить правило на примерах и на всём проекте.

## Подписка компонента

В TSX правило `project/tracked-render` проверяет тип вызываемого значения через TypeScript 7. Вызов Reatom без аргументов при рендере именованного компонента требует `reatomComponent`. Импорт под другим именем и передача атома через props сохраняют его тип. Чистая функция в props остаётся допустимой. Обработчики событий выполняются отдельно от рендера. Правило проверяет прямые вызовы в компоненте и колбэках стандартных итераторов массива. Вызовы внутри произвольной вспомогательной функции требуют ревью. Для реактивного компонента передайте стрелку прямо в reatomComponent.

`project/react-state` проверяет доступ к хукам через объект React, включая псевдоним default-импорта и деструктуризацию. Ограничение именованных импортов дополняет эту проверку.

## Форма компонента

Один компонент на файл. Обычный компонент объявляется через `export const Component = (props: ComponentProps) => …`. Реактивный использует `export const Component = reatomComponent((props: ComponentProps) => …, 'Component')`. Тип props импортируется из соседнего `*.types.ts`. Точка входа `main.tsx` только монтирует приложение и может обходиться без объявления компонента.

Ветку интерфейса выбирайте через `if (...) return ...` и завершающий `return`. Правило `project/component-file` запрещает `let` внутри компонента и создание `atom`, `computed`, `action` прямо в представлении. [Живой пример выбора экрана](../src/features/workspace/workspace-screen.tsx).

## Интервалы между ветками

В теле компонента оставляйте пустую строку перед и после самостоятельного `if`, когда рядом есть другая инструкция. Между двумя ветками достаточно одной пустой строки. Внутри ветки связанный с кнопкой обработчик остаётся рядом с её `return`. Для многострочного кода интервалы можно расставить через `npm run lint -- --fix`. [Пример списка сессий](examples/session-list.tsx).

## Запросы данных

В примере сессий HTTP-функция принимает `AbortSignal`, читает JSON через Ky и возвращает проверенный `Session[]`. Фабрика ресурса связывает её с `computed` и `withAsyncData({ status: true })`. Компонент читает данные и статус, а кнопка вызывает `retry()`. Код ответа и разбор JSON принадлежат API-слою. [API](examples/sessions.api.ts) · [Модель](examples/sessions.reatom.ts).

## Модели, подписки и фабричные компоненты

| Соглашение | Что проверяет Oxlint | Разрешённый пример |
| --- | --- | --- |
| Модель экземпляра создаётся при инициализации | У `reatomFactoryComponent` внешний callback возвращает стрелку рендера. Чтение состояния в инициализаторе и вызов фабрики `create…`, возвращающей атом или объект с атомами, во время рендера дают ошибку. | [Фабричный компонент](examples/page-counter.tsx) |
| Реактивное и разовое чтение выражаются явно | В рендере читайте атом через вызов. Для разового чтения `Atom` или `Computed` в действии, `withCallHook` и `withChangeHook` используйте `peek`. Проверяется также `computed(() => peek(atom))`, включая однострочный возврат в блоке. Сочетание зависимости и снимка разрешено. | [Чтение зависимости и снимка](examples/reactivity-boundaries.ts) |
| Поведение жизненного цикла принадлежит модели | Хуки подключения, отключения, изменения, вызова и ошибки из Reatom объявляются в TS-модуле. Повторное создание одного и того же хука с тем же именованным обработчиком в двух вызовах `.extend()` одного модуля отмечается как дубликат. | [Общее расширение двух моделей](examples/resource-lifecycle.ts) |
| Подписка находится в компоненте, который читает модель | Чтение атома в обычном компоненте требует обёртки. Для простой стрелки, возвращающей JSX из props без вызовов в её теле, достаточно обычного компонента. Явные параметры жизненного цикла у обёртки учитываются. | [Подписанный родитель](examples/page-counter.tsx) и [чистое представление](examples/page-label.tsx) |
| У ресурса один владелец async-состояния | Правило обнаруживает `withAsyncData` вместе с `withAsync` среди аргументов, в цепочке `.extend()` и в отдельных последовательных вызовах для одного идентификатора в общем блоке. | [Отдельные ресурс и команда](examples/reactivity-boundaries.ts) |
| Представление вызывает действие модели | В TSX проверяется прямой вызов `.set()` у значения Reatom. Для примера пагинации правило ловит `Math.ceil(a / b)` и вложенные `Math.min/max`, когда в выражении или имени объявляемой переменной есть обозначение страницы, например `pageSize` или `totalPages`. | [Расчёт и ограничение в модели](examples/pagination.reatom.ts) |

Границы проверок: линтер распознаёт типы в месте вызова и перечисленные конструкции. Решение о том, какие значения должны запускать пересчёт, где извлечь общий смысл из разных обработчиков и какие прочие формулы относятся к предметной области, остаётся на ревью. Примеры нарушений проверяет `npm run docs-lint` по файлу, строке и коду диагностики.
